# Core Loop

```text
User has a shared plan to coordinate in their phone browser
-> LoopedIn shows the next event and its context in the responsive web app
-> user updates attendance, logistics, thread, or photos with thumb-friendly actions
-> the group sees one reliable event record
-> the event becomes a recap/memory after it happens
-> in-app updates and resurfaced memories bring the user back
```

## Primary loop

1. Open the Home screen in a phone browser to see what matters next.
2. Tap into the event detail page.
3. Confirm or change RSVP with one thumb-friendly action.
4. Read the latest thread/logistics context without leaving the event.
5. Add in-app reminders, notes, or photos when those web flows exist.
6. Return through in-app updates and resurfaced memories.

## Current proof point

The Event Detail screen is the core product surface. It must make the event feel like the single source of truth for attendance, logistics, discussion, and memory capture.
